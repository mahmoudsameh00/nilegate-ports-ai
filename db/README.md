# Database files

Two stores (ADR-001): PostgreSQL/PostGIS is the relational system of record; MongoDB holds the semi-structured AIS / EDI data.

| Path | Purpose |
|---|---|
| `schema_snapshot.sql` | `pg_dump --schema-only` of the live PostgreSQL database. **The schema source of truth** (ADR-016). Current file: 2026-09-27, after migrations 001–010 (010 adds rows only). |
| `verify_readonly.sql` | Read-only PostgreSQL audit: row counts, columns, constraints, indexes, data-consistency checks (§13 vessel MMSI, §14 integrity constraints and indexes, §15 roles, comments, statistics, §16 RAG document registry, §17 finance data, §18 finance views and `finance_bi` privileges, §19 invoice audit views, §20 agent state schema and `agent_writer`). It forces `default_transaction_read_only = on`. |
| `check_constraints_reject.sql` | Negative test of migration 006: 14 invalid writes, each must be rejected; everything is rolled back. |
| `create_agent_user.ps1` / `check_agent_user.py` | Create the agents' checkpointer login `ports_agent` (member of `agent_writer`, migration 016) from `.env` (`PG_AGENT_*`) / check it from the host (checkpoint tables writable, DDL and other schemas refused); run `Checkpointer_setup.py` between the two. |
| `create_readonly_user.ps1` / `check_readonly_user.py` | Create the read-only login user from `.env` (`PG_RO_*`, run by the owner) / check it from the host (SELECT works, every write refused). |
| `audit/` | Saved outputs. Latest: `2026-10-08_after_011_report.txt` (equal to the 010 report except §16 ingested 0 → 29; 0 errors) and `2026-09-27_check_constraints_reject.txt` (14/14 PASS). |
| `migrations/NNN_*.sql` | Every PostgreSQL schema change, numbered, applied in order, never edited after being applied. |
| `reference/` | Reference data used by migrations: `itu_mid_table.csv` (ITU Maritime Identification Digits, captured 2026-09-27 from https://www.itu.int/gladapp/Allocation/MIDs) and `flag_country_mid.csv` (reviewed `vessels.flag_country` → MID mapping used by migration 005). |
| `mongo/` | MongoDB container `ports-mongo`: pinned image, commands, numbered `mongosh` scripts and their audit outputs (see `mongo/README.md`). |
| `export_vessels_mirror.py` | Refreshes `Data/processed/synthetic/vessels.csv` from PostgreSQL for database-owned columns (`mmsi`); read-only on the database. |

## Commands (PowerShell, from the project root; container must be running: `docker start ports-postgres`)

Apply one migration:

```powershell
docker cp db\migrations\005_fill_vessels_mmsi.sql ports-postgres:/tmp/m.sql
docker exec ports-postgres psql -U postgres -d ports_logistics -X -v ON_ERROR_STOP=1 -f /tmp/m.sql
```

Refresh the schema snapshot (after every applied migration):

```powershell
docker exec ports-postgres sh -c "pg_dump -U postgres -d ports_logistics --schema-only --no-owner --no-privileges -N tiger -N tiger_data -N topology -f /tmp/schema_snapshot.sql"
docker cp ports-postgres:/tmp/schema_snapshot.sql db\
```

Run the read-only audit:

```powershell
docker cp db\verify_readonly.sql ports-postgres:/tmp/verify_readonly.sql
docker exec ports-postgres sh -c "psql -U postgres -d ports_logistics -X -f /tmp/verify_readonly.sql > /tmp/verify_report.txt 2>&1"
docker cp ports-postgres:/tmp/verify_report.txt db\audit\YYYY-MM-DD_verify_report.txt   # replace YYYY-MM-DD with today
```

Refresh the `vessels.csv` mirror after a change to a database-owned column (`mmsi`, plan decision D7). The export
writes only when every generator-owned column is identical to the database, and keeps the file's CRLF line endings:

```powershell
uv run python db/export_vessels_mirror.py
```

## Container `ports-postgres` (ADR-034)

Re-created on 2026-09-27 on the same volume and image, published on **127.0.0.1 only**. `.env` must use
`PGHOST=127.0.0.1`: with `localhost`, Windows tries IPv6 `::1` first and every connection waits ~5 s before falling back.

```powershell
docker stop ports-postgres; docker rm ports-postgres   # the data lives in the named volume, not in the container
docker run -d --name ports-postgres -p 127.0.0.1:5432:5432 -v ports-postgres-data:/var/lib/postgresql/data postgis/postgis:16-3.5
```

The `POSTGRES_*` init variables are not needed: the volume is already initialised. Verified: data identical before / after
(500 / 19,990 / 1,000 rows, 71 constraints), port 5432 closed on every LAN address, `SyntheticGenerator.ipynb` 28/28.

## Known points

- Owner actions done 2026-09-28: read-only login user created (`db/check_readonly_user.py` 8/8); the orphan anonymous
  volume of 2026-09-12 (an old PostgreSQL 16 cluster, 108 MB) was deleted. The remaining anonymous volume belongs to
  `ports-mongo` (`/data/configdb`, declared by the image).
- Docker Desktop does not start the containers by itself (no restart policy): after a reboot run
  `docker start ports-postgres ports-mongo`.

- `pg_hba.conf` trusts connections made **inside** the container (image default); from the host every login needs a
  password (`scram-sha-256`), and the port is reachable from this machine only.
