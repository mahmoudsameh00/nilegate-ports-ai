# من الداتا للـ System — دليل الفايدة والمعالجة

هدف الملف ده: كل مصدر بيانات عندنا **هيخدم إيه بالظبط**، **هيتعالج إزاي**، وكل ده بيوصلنا لـ **إيه في الآخر**.

---

## 1. الفايدة — كل مصدر هيخدم إيه في السيستم

### أ) الأساس الـ Structured (PostgreSQL)

| المصدر | هيتحول لإيه | فايدته في السيستم |
|---|---|---|
| `attributed_ports.geojson` | جدول `ports` | **المرجع الجغرافي الأساسي**: 856 ميناء بإحداثيات حقيقية + اسم + دولة + كود وظيفة (Function) — أي جدول تاني (vessels, containers, AIS) هيربط بيه عن طريق LOCODE |
| `port_flows.shp/.dbf` | جدول `port_connections` | شبكة العلاقات بين الموانئ (مين متصل بمين وبإيه حجم تدفق) — أساس أي تحليل شبكي أو خريطة تدفقات في Power BI |
| Suez Canal Tolls PDF | جدول `toll_rates` | **مرجع تسعير حقيقي** — بيمنع أرقام الـ `invoices` الاصطناعية إنها تطلع بعيدة عن الواقع |

### ب) الطبقة الـ Semi-structured (MongoDB)

| المصدر | هيخدم إيه |
|---|---|
| `ais_data.json` (10,000 سفينة من AISHub) | **تنوع الأنواع**: يوريني كل أنواع السفن وحالات الملاحة (NAVSTAT) الحقيقية الموجودة، عشان الـ generator يعرف يوزّع القيم بشكل واقعي مش عشوائي |
| `NOAA_AccessAIS.csv` (54 سفينة، 856 لحظة زمنية) | **فيزياء الحركة**: يوريني إزاي سفينة حقيقية بتتحرك لحظة بلحظة (سرعة، اتجاه، توقف) — ده اللي هيخلي الـ AIS المُولّدة تتحرك بمنطق فيزيائي مش random walk |
| `IFTMIN_D12A_sample.edi` | **قالب الصياغة الرسمية**: يوريني الشكل الصحيح لرسالة EDIFACT حسب المعيار الدولي — الـ generator هيملى نفس البنية بقيم متغيرة |

### ج) طبقة الـ RAG (Qdrant + Postgres metadata)

| المصدر | هيخدم إيه |
|---|---|
| HbR Annual Report (Rotterdam) | نموذج لتقرير سنوي حقيقي — استراتيجية، ESG، أرقام مالية. بيدرّب الـ RAG على أسئلة زي "إيه استراتيجية الشركة تجاه الاستدامة؟" |
| LPI 2.0 + Methodology (World Bank) | بيانات أداء لوجستي مقارنة، فيها مثال جاهز لمصر. بيدرّب الـ RAG على أسئلة benchmarking زي "إزاي أداء مصر مقارنة بالمنطقة؟" |
| IMO MSC-MEPC Circular | **مرجع + schema مزدوج**: هو نص RAG عادي (سؤال "إيه معايير تقارير الحوادث؟")، وفي نفس الوقت schema حقيقي لجدول `incident_reports` |
| USCG BOIR Report | **مرجع + قالب أسلوب مزدوج**: نص RAG عن تقييم مخاطر الموانئ، وكمان "صوت" حقيقي (لغة، هيكل، توصيات) نستخدمه كـ few-shot لتوليد تقارير حوادث مشابهة |
| FBL Template (FIATA) | **مرجع + قالب مزدوج**: نص RAG عن شروط النقل (المسؤولية، التأمين، إلخ)، وكمان القالب الحرفي لتوليد عقود شحن synthetic |

### د) خارج الـ Database بالكامل

| المصدر | ليه برا |
|---|---|
| الأخبار/المستجدات | مش corpus ثابت — الـ agent هيستخدم `web_search` كـ tool call لايف وقت السؤال بس |

## 2. خطة المعالجة (Processing Plan) — بالترتيب

### المرحلة A — الأساس الـ Structured (نبدأ بيها)
1. تنظيف `attributed_ports.geojson` (شيل الـ artifact الزايد) → تحميله في جدول `ports`
2. استخراج جدول الـ attributes من `port_flows.dbf` → تحميله في `port_connections` مع FK على `ports.LOCODE`
3. استخراج أرقام الرسوم من PDF قناة السويس (يدوي أو بـ `pdfplumber`) → جدول `toll_rates`
4. بناء generator للجداول الاصطناعية (`vessels`, `containers`, `invoices`, `employees`, `roles`, `departments`) — مربوط بالمراجع اللي فوق

### المرحلة B — الـ Semi-structured
5. تحليل إحصائي لـ `ais_data.json` + `NOAA_AccessAIS.csv` (توزيع السرعات، الاتجاهات، أنواع السفن) → بناء config لمولّد AIS واقعي
6. تفكيك `IFTMIN_D12A_sample.edi` لقالب segments (`NAD`, `LOC`, `TDT`, `EQD`...) → بناء مولّد EDI يملى نفس البنية بقيم متغيرة

### المرحلة C — الـ RAG Ingestion
7. تقطيع (chunking) كل مستند حقيقي (HbR, LPI, IMO, USCG, FBL) → embedding → تخزين في Qdrant مع `sensitivity_level` و `department` لكل chunk
8. توليد `incident_reports` اصطناعية (few-shot من USCG + schema من IMO) → نفس مسار التقطيع والتخزين
9. توليد عقود Bill of Lading اصطناعية (من قالب FBL) → نفس مسار التقطيع والتخزين

### المرحلة D — التحقق
10. اختبار RBAC: نفس السؤال من 3 أدوار مختلفة (employee/manager/ceo) والتأكد إن الفلترة شغالة صح
11. اختبار الاتساق السببي: التأكد إن حالة الشحنة في Postgres متوافقة مع حركتها في AIS ومع أي incident report مرتبط بيها

## 3. عشان نوصل لإيه (الهدف النهائي)

في آخر المراحل دي، هيكون عندنا:

- **قاعدة بيانات polyglot كاملة وشغالة** (PostgreSQL + MongoDB + Qdrant) فيها بيانات واقعية (مزيج حقيقي/synthetic مربوط ببعضه منطقياً)
- **نظام RAG بيفلتر حسب الصلاحيات** فعلياً وقت الاسترجاع، مش بعده
- **أساس جاهز لطبقة الـ Agents** اللي جاية بعد كده — هتقرأ من نفس القواعد التلاتة وتولّد تقارير Power BI الدورية
- **بيئة تعلم غنية** فيها كل أنواع الداتا (structured/semi/unstructured) عشان تتعلم RAG على سيناريوهات واقعية مش مبسّطة

الخطوة الجاية المباشرة بعد الملف ده: نفّذ المرحلة A فعلياً بالكود.
